# VeilForge V4 Release Candidate 1 Known Limitations

## Compiler support

The release candidate supports the pinned Solidity compiler baseline 0.8.24. Other compiler versions, language constructs not represented by the current lowering pipeline, malformed projects, and unresolved imports can produce explicit unsupported or incomplete outcomes.

## Analysis boundary

- Dataflow is conservative and budgeted; recursion, unknown external behavior, dynamic function pointers, unresolved aliasing, inline assembly, and low-level return values can remain incomplete.
- Known low-level or delegatecall arguments may be proven disclosures independently, but consumed unknown return values remain fail-closed.
- Dynamic storage writes with unresolved keys remain alias-incomplete. Direct classified storage reads can still prove disclosure without identifying a concrete key.
- Supported ABI encoders and cryptographic hash builtins preserve provenance. New or compiler-specific builtin shapes need dedicated coverage.

## Detector and corpus scope

The release detector catalog covers Arc Payments, Arc Treasury, and Arc Private Credit. The 60-case oracle is a bounded release corpus, not a proof of correctness for arbitrary Solidity programs or business semantics. Findings require engineering and policy review; absence of a finding is not a general confidentiality guarantee.

## Policy and privacy

Policy dispositions model declared public fields, approved declassification wrappers, accepted risks, and suppression records. Incorrect policy input can change dispositions, so policy provenance and review remain operational responsibilities. Reports deliberately retain evidence and source regions; consumers must handle report artifacts as potentially sensitive security data.

## Runtime and deployment

- The SDK and CLI require Node.js 20 or newer.
- Compilation and analysis can be CPU- and memory-intensive on large projects; stage/global budgets can end a scan as incomplete.
- SARIF rendering and the GitHub Action are Node/CI integrations. They are not browser-native APIs.
- The current web application remains on the V3.2 schema and synchronous browser analyzer. It does not yet consume V4 SDK reports.
- Registry, proof, on-chain publication, package publication, tags, releases, and deployment are outside this release-integration phase.

## Version label

The human-facing candidate name is “VeilForge V4 Release Candidate 1.” Repository packages, benchmark metadata, and schemas currently identify the artifact as `4.0.0-gc.1`; Phase 5A does not partially rename this contract to `4.0.0-rc.1`.
