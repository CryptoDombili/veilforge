# VeilForge V4 Release Candidate 1

VeilForge V4 Release Candidate 1 is the integrated grant-candidate baseline for the compiler-backed VeilForge analysis pipeline. The release name uses RC1 terminology; the repository artifact version remains `4.0.0-gc.1` because the SDK, CLI, SARIF, gate, benchmark oracle, schemas, and generated metadata currently share that established candidate contract. No package version is changed in Phase 5A.

## Release baseline

- Corpus coverage: 60/60 cases passed.
- Findings: 56 true positives, 0 false positives, 0 false negatives.
- Precision, recall, and F1: 1.0.
- Release gate: `passed / allow`; gate false negatives: 0.
- Negative-corpus false positives: 0.
- Calldata regression: 3 TP / 0 FP / 0 FN.
- Unsafe locations, integrity failures, and nondeterministic results: 0.
- Benchmark oracle: unchanged, version 1.0.0.

## What is included

### Compiler-backed analysis

V4 compiles exact Solidity 0.8.24 standard JSON input and builds a compiler-backed AST index. It lowers compilation output into a stable intermediate representation, control-flow graphs, and a call graph before running intraprocedural and interprocedural dataflow.

### Financial privacy domains

The candidate ships deterministic detector packs for three Arc financial domains:

- Arc Payments
- Arc Treasury
- Arc Private Credit

The packs classify financial sources and disclosure sinks, apply policy dispositions, retain evidence and traces, and group occurrences by stable detector and semantic sink identity.

### Deterministic reports and exports

Canonical findings and reports include stable detector identities, source regions, evidence, traces, dispositions, incomplete-analysis reasons, and integrity metadata. Report schema 4.1.0 uses `veilforge.report.hash.v2`; verification support for report schema 4.0.0 and hash payload v1 remains available. Deterministic JSON, Markdown, export packages, and SARIF 2.1.0 are integrity-checked.

### CLI and SDK

The ESM SDK exposes one-call and staged scanning, abort/timeout handling, progress reporting, immutable public results, and report/export verification. The isolated CLI provides source discovery, worker execution, atomic output, stable exit codes, SARIF generation, policy gating, and benchmark commands.

### CI and policy gate

The GitHub Action runs the V4 CLI in Node 20, emits verified SARIF and exports, and exposes an allow/deny gate decision. The deterministic policy gate supports severity/disposition thresholds and verified baseline comparison.

### Benchmark oracle

The fixed oracle contains 60 positive, negative, and adversarial cases across the three domains. The release-quality gate requires complete coverage, zero gate false negatives, zero negative false positives, safe source locations, verified integrity, and deterministic results.

## Privacy model

Analysis is local-first and deterministic. Source code is compiled and analyzed locally; operational metadata is excluded from canonical report hashes by default. Reports expose evidence needed to explain a finding while avoiding unrestricted source-content publication. Policy-approved, accepted-risk, incomplete, and detected outcomes remain explicit rather than being collapsed into a single severity score.

## Compatibility

- Node.js: 20 or newer.
- Solidity compiler: exact supported baseline 0.8.24.
- Report schema: 4.1.0; legacy 4.0.0/hash v1 verification retained.
- Finding schema metadata: 1.1.0 in canonical reports; standalone V4 finding schema is versioned 4.1.0.
- SARIF: 2.1.0.
- Benchmark oracle: 1.0.0.
- Candidate artifact version: `4.0.0-gc.1`.

## Web status

The existing browser application remains on the V3.2 report and engine contract. Phase 5A does not connect the UI to V4. A separate adapter-and-worker migration is required before the browser can consume V4 reports safely.
